## 1. 环境准备

### 1.1 两种运行栈（二选一）

- **标准栈**：需 Docker Desktop 可用 → `bash start-stack.sh`（MySQL/Redis 容器 + jar + 前端，见 §9）。
- **降级栈（本机已验证可用）**：原生 MySQL 9.5 + `%LOCALAPPDATA%\Temp\blogg-redis-lite.js` + 既有 `backend/target/blog-backend.jar` + 3000 前端。`F:\_blogg_shim\` 把 `docker exec` 转真实 SQL/RESP，**依赖容器的探针一律走 `node F:/_blogg_shim/run-probe.js tools/<脚本>.js`**。本机沙箱拦截 Docker，`daemon.json` 写被拒，默认走降级栈。

### 1.2 启动后端（单测/验收前，若 8081 未存活）

```bash

  -Dmaven.multiModuleProjectDirectory="$ROOT_WIN/backend" \
  org.codehaus.plexus.classworlds.launcher.Launcher -f backend/pom.xml -q -DskipTests package
```

### 1.3 预置账号与前置清理

- `verify-p3.js` 默认假定账号 `13800000333 / testpass123` 已存在（环境变量 `P3_PHONE` / `P3_PASS` 可改）。**批次一先确保它存在**：用 `p3_smoke_test.sh` 自注册（其随机手机号），或手动 `curl /api/register`。注册前确认 `BLOG_SECURITY_REGISTER_LIMIT_IP=8` 已生效（否则 IP 限流 200 也可能在批量注册时触发）。
- 每个依赖全栈的脚本跑前清限流键（降级栈由 `redis-cli-shim.js` 把清键 EVAL 翻译成真实 `KEYS`/`DEL`）：
  ```bash
  docker exec -i blogg-redis redis-cli EVAL \
    "local k=redis.call('KEYS','ratelimit:*'); for i,v in ipairs(k) do redis.call('DEL',v) end; return #k" 0
  ```
- `verify-stack.js` 的 `userCount===0` 是空库假设：存量账号会得 35/36。处理：`mysqldump --set-gtid-purged=OFF` 全表备份 → 清空 `user` → 跑 → 恢复；且跑前还要清 `blog:session:*` / `ratelimit:*`（残留会话键会引发登录/TTL 连锁假失败）。

## 3. 执行顺序（按轮次，轮间必清限流）


## 5. Review 发现的覆盖缺口与补充测试

以下 9 项是**实勘现有脚本后确认尚未被自动断言**的点，需补测（或补脚本）才能满足 §9 口径，否则会出现「脚本全绿但口径未证伪」的假安全。

### 5.1 改密后「旧第二会话」失效未断言（口径③核心）
`verify-p3.js` 只验证了「旧密码登录 401 + 新密码可登录」，**未用另一个已登录令牌验证其失效**。`AccountService.changePassword` 已正确调 `deleteOthers(uid, currentToken)`，但脚本没证伪。
**补测**：用 `phone` 登录两次拿 `tokA`/`tokB`；`tokA` 改密；随后 `GET /api/me` 带 `tokB` 必须 **401**，`tokA` 仍 200。可临时加进 `verify-p3.js` 的 `testAccount`，或在 `p3_smoke_test.sh` 里用已打印的 `TOKEN1` 做该断言（脚本已留 `TOKEN1(旧会话) after pw change` 探针位，仅打印未判等）。

### 5.2 remember 长短期 TTL 与有效期至一致性未断言（口径④）
`verify-p3.js`/`p3_smoke_test.sh` 均未校验 Redis TTL 区间与 `/api/me` 的 `expiresAt` 是否匹配。`SessionStore` 实现正确（`REMEMBER_TTL_MS=30d` 绝对上限滑动、`SESSION_TTL_MS=12h` 不续期），但无断言。
**补测**：
```bash
# remember=true 登录，取 token；查 Redis TTL 应 ∈ [29.5d, 30d]，且 /api/me 的 expiresAt 与之吻合
curl -s -X POST localhost:8081/api/login -H 'Content-Type: application/json' \
  -d '{"phone":"...","password":"...","remember":true}'
# TTL 查询（降级栈走 redis-cli-shim，仅支持基础命令；TTL 可用则核验）
docker exec -i blogg-redis redis-cli TTL "blog:session:<token>"
```
断言：`remember=true` 的 TTL ≥ 2592000-容差 且 `/api/me` 的 `session.expiresAt` 距 now 在 [29.5d,30d]；`remember=false` TTL ∈ [11.5h,12h] 且**不续期**（两次 `me` 后 TTL 不增大）。

### 5.3 越权 404 用 owner 自读代替第二账号
`verify-p3.js` `testVault` 注释明确「无第二账号时跳过」，仅验证 owner 读私有集合 200，**未证伪**他人读私有返回 404。`ContentTargetService` 默认分支抛 `NOT_FOUND` → 404，实现正确但无自动化证伪。
**补测**：在 `verify-p3.js` 内用第二个预置账号（`P3_PHONE2`）登录，读第一个账号的私有 collection/media/moment → 必须 401/404；对公开集合分享页用错误口令 → 403。

### 5.4 影视「零托管文件」未自动断言（口径②）
`V5` 表结构已确认 `media_item` 无 blob/object_key/mime/size/播放源字段（仅 `external_url` 纯文本），但 `verify-p3.js` 没有运行期断言证明「库里真的没有文件列 / uploads 目录没有影视文件」。
**补测**（一次性 SQL + 目录枚举）：
```sql
SELECT COLUMN_NAME FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA='blog' AND TABLE_NAME='media_item'
  AND (COLUMN_NAME LIKE '%blob%' OR COLUMN_NAME LIKE '%file%' OR COLUMN_NAME LIKE '%object%'
       OR COLUMN_NAME LIKE '%mime%' OR COLUMN_NAME LIKE '%size%' OR DATA_TYPE IN ('blob','mediumblob','longblob','binary'));
-- 期望：0 行
```
并 `ls web/uploads | grep -iE '\.(mp4|mkv|avi|m3u8)$'` 期望无影视文件。

### 5.5 外链失效探测 `link_status` 未测（口径②「只标记不删除」）
`media_item` 有 `link_status`/`link_checked_at_ms`/`link_fail_count`，但无脚本验证「探测后记录仍在且仅状态变更、不删除」。
**补测**：取一条 media，手动 `UPDATE media_item SET link_status='invalid'`；触发探测（若有时钟/端点）后断言该行仍在、《且其它字段未被清空；验证「失效只标记不删」语义。

### 5.6 游标分页「无重复/无遗漏/单调」未做多页断言（W3 完成定义）
`verify-p3.js` 只测了「篡改游标 400」和「超 500 字 400」，**未做连续插入 N 条后翻页收集、断言无重复 id / 无遗漏 / created_at 单调**。
**补测**：插入 N=20 条 moment；用 `before=` 翻 3 页（每页 10）收集全部 id；断言 `ids.length===20`、无重复、`created_at_ms` 严格递减（或按 (created_at_ms,id) 单调）。

### 5.7 评论审核对新 target 的 viewer 可见性未测（W7）
`verify-p3.js` 只测了「对 public media 评论/点赞 200」，**未测待审评论对非作者/匿名不可见**。`CommentService` 有 viewer 过滤逻辑，但媒体类 target 缺自动化证伪。
**补测**：对 media 发一条评论（默认 `pending`）；用第二账号/匿名 `GET /api/comments?target_type=media&target_id=...` → 不应包含该 pending 评论；作者本人可见。

### 5.8 分享只读页 `noindex` 未断言（W7）
`share.html` 应加 `noindex` meta 防止索引。`verify-p3-ui.js` 静态/浏览器探针未检查。
**补测**：在 `verify-p3-ui.js` 的 `share.html` 静态校验里加 `html.includes('noindex')` 断言；或浏览器探针读 `<meta name="robots">` 内容。

### 5.9 P3 源码基线未确认是否刷新
`p0-baseline.json` 语义是「源码连续性」；P3 改了 `HomeService`/`ContentTargetService`/`SessionStore`/`AccountService`/`AccountController`/`MediaController` 等 10+ 既有文件。若 `tools/p0-baseline.json` 未加 `p3Modified` 且 57 个 SHA256 未重算，**`p0-probe.js` 第 1 节会失败**。
**补测**：执行前先离线校验：
```bash
node -e "const fs=require('fs'),c=require('crypto'),p=require('path'),b=require('./tools/p0-baseline.json');let d=[];for(const [r,h] of Object.entries(b.files)){const f=p.join('.',r);if(!fs.existsSync(f)){d.push(r);continue}if(c.createHash('sha256').update(fs.readFileSync(f)).digest('hex')!==h)d.push(r)}console.log('diffs',d.length,d)"
```
若 `diffs>0`：重算 57 个 SHA256 写入 `files`，新增 `p3Modified` 字段，保留 `p0Snapshot`/`p1Modified`/`p2Modified`，再跑 S3。

## 6. 防回归硬规则（踩坑固化）

1. **改既有文件必须刷新基线**：P3 触碰 10+ 既有源码，实现后必须更新 `p0-baseline.json` 并加 `p3Modified`，否则 S3 第 1 节失败（见 §5-9）。
2. **限流键隔离**：S8 与 S10、S9 与 S11 之间必须再清 `ratelimit:*`；环境变量正确键是 `BLOG_SECURITY_REGISTER_LIMIT_IP`（非 `BLOG_REGISTER_LIMIT_IP`）。
3. **空库假设**：S7 用 `userCount===0`；存量账号 35/36，按 §1.3 备份→清空→跑→恢复。
4. **Windows delete-pending**：临时浏览器副本清理不能只信 `existsSync()`（会误报已删）。现有 `verify-p2-ui.js`/`verify-p3-ui.js` 用 `fs.unlinkSync` + 失败忽略；若发现残留，参照 `verify-p2-layout.js` 改用「启动自愈扫描 + `readdirSync()` 枚举判据 + 有限重试」。
5. **断言原则**：查「危险行为是否被拒绝」而非「字面量是否出现」。XSS 断言查「不生成危险标签/属性」；被拒语法降级为转义纯文本时字面量本应保留——**修断言不改实现**。
6. **零外链**：新增 JS/CSS 必须本地化 `web/vendor/` 并过 `checkVendor()`；`selfcheck.js` 反向注入必须保持 6 类全中（删闭合标签/CDN 外链/悬空锚点/破坏 DOM id/删关键资源/品牌回退）。

## 8. 风险与备注

- 本机 Docker 不可用，标准栈需用户在非受限终端启动；降级栈已验证 11 套全绿历史（2026-11-12），但四常驻进程（mysqld/redis-lite/8081/3000）会话切换后可能被回收，跑前先 `curl /api/health` 探活。
- `verify-p3.js` 自带自清理（删除创建的 media/collection/moment），但 `p3_smoke_test.sh` 会**残留测试账号**（仅打印 PHONE/PASSWD 供手动清理），批量跑后需运维层限定清理，勿擅自改已实现的脚本。
- P3 的「外链失效探测」「游标多页」「分享 noindex」三项在现有脚本里完全缺失断言（§5-5/6/8），若要在本轮交付「可执行测试」，建议优先补这三条补测命令或最小脚本，否则 §9 口径②/① 只靠人工确认。
