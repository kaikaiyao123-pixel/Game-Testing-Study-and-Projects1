## 0. 范围界定与口径

### 0.1 需求解读

「根据前端设计相对应的功能」= 以现有页面**实际存在的入口、占位与交互**为输入，逐项定义其业务功能、数据模型、接口契约、权限边界与实施顺序。

- 已实现部分（登录 / 注册 / 会话 / 登出）作为**能力基线**，只分析其「需要补强」的点，不重复设计。
- 未开放部分（4 个导航项、2 个下拉菜单项、主页内容区）作为**本方案的设计主体**。
- 输出为方案，不产出可运行代码，不改变仓库现状。

### 0.3 后端能力基线

| 类别 | 现状 |
| --- | --- |
| API | `GET /api/health`、`POST /api/register`、`POST /api/login`、`GET /api/me`、`POST /api/logout`，共 5 个 |
| 响应风格 | `{ ok: true, message, ... }`；失败由 `GlobalExceptionHandler` 统一处理 |
| 鉴权 | `Authorization: Bearer <token>` → Redis `blog:session:<token>` → `userId`；登出即删键 |
| 会话 | Redis，TTL 由 `blog.session.ttl-seconds` 配置，默认 604800 秒（7 天）；无滑动续期、无用户维度的会话索引 |
| 用户表 | `user`：`id`(UUID CHAR36)、`phone`(唯一)、`nickname`、`password_hash`(PBKDF2)、`created_at_ms`、`last_login_at_ms`、`login_fails`、`locked_until_ms` |
| 安全 | 登录失败 5 次锁定 60 秒；时间统一 epoch 毫秒 BIGINT，规避 JDBC/JVM 时区 8 小时偏移 |
| 技术栈 | Java 17、Spring Boot 3.3.5、`spring-boot-starter-web` + `jdbc` + `data-redis`、mysql-connector-j；**无 JPA / MyBatis、无 Spring Security、无文件存储、无对象映射层** |
| 前端通信 | `web/js/api.js` 为唯一边界，`API_BASE` 指向 `http://127.0.0.1:8081`，令牌存 Web Storage，`credentials: 'omit'` |
| 部署 | 3000 静态前端（`server/frontend.js`）+ 8081 API + 3306 MySQL + 6379 Redis；容器只跑本地已有镜像 |

### 0.4 本方案边界（不做什么）

1. 不写代码，不修改任何现有文件（本文档为新增交付物）。
2. 不改变现有 5 个鉴权 API 的响应字段，保证 `web/js/api.js` 与页面无需被动改动。
3. 不引入短信网关、第三方 OAuth、消息队列、Elasticsearch 等新中间件 —— 受「Docker Hub 不可达」与「零外部依赖」双重约束。
4. 影视资源**允许登记外链与网盘索引**（决策 3），但仍不上传、不托管、不转存文件本体，不提供在线播放源，不主动爬取或批量分发第三方资源（见 F3）。
5. **本轮不做** HttpOnly Cookie 会话改造（决策 5：独立阶段，归入 P4）。
6. 不设置导航功能开关：5 项导航与 2 个下拉项在同一批次全部启用（决策 6）。

## 1. 总体设计原则

| 编号 | 原则 | 说明 |
| --- | --- | --- |
| P1 | 契约优先 | 新增接口沿用 `{ ok, message, data }` 风格与 Bearer 会话；在 `web/js/api.js` 中扩展方法，不改 `request` 内核与页面直连 fetch |
| P2 | 复用而非重建 | 鉴权统一从 Redis 会话解析 `userId`。当前无 Spring Security，应引入**一个**统一拦截器做令牌解析与上下文注入，避免每个新 Controller 重复写解析逻辑 |
| P3 | 三级权限 | ① 公开读（已发布且公开）② 登录读（私有内容）③ 作者写（仅 owner）。写操作一律校验 `owner_id == session.userId` |
| P4 | 主键与时间统一 | 主键 UUID `CHAR(36)`；时间 epoch 毫秒 `BIGINT`；沿用现有约定 |
| P5 | 软删除 + 状态机 | 内容统一带 `status`（draft / published / archived）与 `deleted_at_ms`，不做物理删除 |
| P6 | 统一分页 | 入参 `page`（从 1）、`size`（默认 20，上限 50）、`sort`；出参 `{ items, total, page, size }`。高频插入的时间线另用游标分页 |
| P7 | 文件不入库 | 图片 / 头像只在库中存相对 URL 或对象键；二进制落磁盘或对象存储 |
| **P8′** | **一次性全量启用** | 决策 6：不设功能开关，5 项导航 + 2 个下拉项同批次全部转为可用链接。前提是**所有目标页面在该批次内一并可用**，不允许导航指向 404 或白屏页；空态设计必须完备 |
| **P9** | **匿名读 / 登录写分离** | 决策 2：公开内容允许匿名读；发布、编辑、评论、点赞、上传、资料与设置等写操作一律要求登录。站点开放不等于开放匿名写 |
| **P10** | **互动横切复用** | 决策 7：评论 / 点赞 / 分享统一用「目标类型 + 目标 ID」多态关联附加到 F2 / F3 / F4 / F5，不改各内容表结构，不新增导航项 |

## 2. 功能模块设计

### F0 账号与会话（基线补强，非新页面）

现有能力：注册、登录、`/api/me`、登出、失败锁定、PBKDF2 口令散列。需补强项：

| 编号 | 功能 | 设计要点 |
| --- | --- | --- |
| F0-1 | 「保持登录状态」服务端语义 | 现状缺陷：复选框只影响 Web Storage 位置，服务端 TTL 恒为 7 天，语义不一致。设计：登录接口接收 `remember` 布尔值；勾选 → 长 TTL（建议 30 天）+ 滑动续期；未勾选 → 短 TTL（建议 12 小时）+ 不续期。滑动续期须设**绝对上限**，避免永久有效；续期时同步更新会话的 `expiresAt`，保证主页「有效期至」显示正确 |
| F0-2 | 会话管理 | 现状 Redis 只有 `token → session` 正向键，无用户维度反向索引。设计：新增用户会话集合索引（如 `blog:user-sessions:<userId>`），支持列出活跃设备（UA / IP / 创建时间 / 最近活动）、单设备踢下线、全部登出。登出与会话过期须同步清理索引，防止脏数据 |
| F0-3 | 修改密码 | 校验旧密码 → 更新 `password_hash` → 使**除当前会话外**全部会话失效；与 F7 安全分区共用 |
| F0-4 | 找回密码 | 在「未接短信网关」前提下不伪造验证码。建议预留接口 + 人工重置或邮箱链接；若必须自助，需先确认短信 / 邮件通道，否则不做 |
| F0-5 | 登录审计 | 登录接口已采集 IP 与 User-Agent，落 `login_log` 表（时间、IP、UA、结果、失败原因），供 F7 展示与异常排查 |
| F0-6 | 生产安全加固 | README 已列限制：HTTP + CORS `*` + 令牌存 Web Storage。改为 HTTPS + HttpOnly Secure Cookie + 具体 CORS 域名 + 令牌轮换。**决策 5：独立阶段（P4），本轮不动** |
| **F0-7** | **开放注册风控** | 决策 2 新增：站点开放注册后，需补注册频率限制（按 IP / 设备，Redis 计数）、昵称敏感词过滤、手机号唯一约束沿用现有 `uk_user_phone`、注册后不自动发放高权限（本站无角色分级，仅作者本人）。不引入短信验证码（无网关） |

### F1 主页（导航第 1 项，改造现有 Hero）

现状：Hero 只有欢迎语与三项会话元信息，本质是「登录成功回执」，不是内容首页。

设计目标：改造为**站点聚合首页**，保留原有账号状态信息但降级为小卡。

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 欢迎卡 | 登录态显示「欢迎回来，昵称」与会话元信息（绑定手机号脱敏、本次登录、有效期至）；**访客态显示站点简介与「登录 / 注册」入口** | `/api/me`（可选调用） |
| 统计卡 | 文章数、影视条目数、宝库条目数、碎碎念数 | 聚合查询 |
| 最近动态 | 跨模块时间线，取最新 N 条（文章 / 影视 / 宝库 / 碎碎念），标注来源类型 | 各模块按 `created_at_ms` 归并 |
| 快捷操作 | 写文章、记一条碎碎念、添加影视条目、新建收藏集合；**仅登录态显示** | 依登录态渲染 |

补充设计：
- **空态优先**（P8′ 硬要求）：任一模块无数据时显示引导文案与「去创建」入口，不渲染一片「0」的卡片。因导航一次全开，页面壳上线时内容可能为空，空态必须同批交付。
- **缓存策略**：首版直接多表查询；数据量上升后用 Redis 缓存首页摘要（写操作主动失效），不建议引入定时全量重建。首页为公开读，缓存键不带用户维度。
- **品牌统一（决策 8）**：站点显示名统一为「炫与梓」，登录页标题、副标题、`<title>` 与主页品牌一致；抽为站点配置项（配置表或 `config.js` 常量），避免多处硬编码。保留用户手动修改的「炫与梓」文案本身。

### F2 文章（导航第 2 项）

定位：长内容发布与阅读，博客核心模块。

**内容模型（字段清单）**

| 实体 | 关键字段 |
| --- | --- |
| 文章 | `id`、`author_id`、`title`、`slug`、`summary`、`content_md`、`content_html`、`cover_url`、`status`、`visibility`、`category_id`、`published_at_ms`、`view_count`、`created_at_ms`、`updated_at_ms`、`deleted_at_ms` |
| 分类 | `id`、`owner_id`、`name`、`slug`、`sort_order` |
| 标签 | `id`、`name`、`slug` |
| 文章-标签关联 | `article_id`、`tag_id`（联合唯一） |

**功能设计**

1. **编辑（决策 4）**：引入**第三方 Markdown 编辑器库**，按 §7 要求完整本地化到 `web/`。编辑器只负责输入与预览；**服务端**负责渲染 HTML 并执行白名单净化（关键安全点，禁止把用户提交的 HTML 原样输出）。摘要可由正文前 N 字自动生成；`slug` 唯一，冲突时追加序号。
2. **状态机**：草稿 → 发布（写 `published_at_ms`）→ 归档；草稿仅作者可见。
3. **阅读**：列表支持分页、分类 / 标签筛选、关键词搜索（首版对 `title` + `summary` 做前缀匹配）；详情按 `slug` 或 `id` 访问；上一篇 / 下一篇；浏览量用 Redis 计数并定期落库，避免每次阅读都 `UPDATE` 主表。
4. **互动（决策 7，纳入首版）**：文章详情挂载评论区、点赞按钮、分享按钮，统一走 F8，不在文章模块内重复实现。
5. **权限**：公开列表只返回 `status=published` 且 `visibility=public` 且未删除的行，匿名可读；作者可读取自己的全部状态；写操作仅作者且必须登录。

### F3 影视资源（导航第 3 项）

定位：**个人观影资料库 / 外链索引**，不是视频站。

> **合规口径（决策 3 已放宽，保留以下底线）**：
> - **允许**：登记外部链接、网盘索引（链接 + 提取码 + 来源平台 + 来源标注）、个人观看记录、封面外链。
> - **仍不做**：不上传、不托管、不转存影视文件本体；不提供在线播放源；不主动爬取或批量分发第三方资源；网盘链接不做自动解析 / 自动跳转，只作为纯文本索引展示。
> - **配套**：每条外链标注来源与录入者；提供失效标记与定期有效性探测；页面加「资源来自第三方，本站不存储、不保证可用性」的免责说明。

**内容模型（字段清单）**：`id`、`owner_id`、`title`、`original_title`、`type`（电影 / 剧集 / 动画 / 纪录片）、`year`、`region`、`director`、`cast_summary`、`rating`（个人评分）、`poster_url`、`external_url`、`link_source`（来源平台）、`link_code`（提取码，可选）、`link_status`（有效 / 失效 / 未检）、`link_checked_at_ms`、`watch_status`（想看 / 在看 / 已看）、`watched_at_ms`、`progress`（剧集集数）、`note`（短评）、`visibility`、`tags`、`created_at_ms`、`updated_at_ms`、`deleted_at_ms`。

**功能设计**

1. 卡片墙 / 列表双视图；按类型、年份、观看状态、评分、链接状态筛选；关键词搜索。
2. 个人评分与短评；「想看清单」独立视图；剧集观看进度记录。
3. 外链有效性检测：后台定时探测（低频、带退避），标记失效但不删除；不对目标站点发起高频请求。
4. 去重：以「标题 + 年份 + 类型」做业务唯一约束。
5. **可见性（决策 2）**：默认 `public`，匿名可读元数据与外链索引；作者可设为私有。**写操作（新增 / 编辑 / 评分 / 标记）仅登录作者**。
6. 首版不做封面上传，只存 URL；上传能力统一由 §6 的上传端点提供。
7. 互动（决策 7）：条目详情挂载评论 / 点赞 / 分享，走 F8。

### F4 げん的宝库（导航第 4 项，决策 1 定稿）

**定位（已确认）**：私人收藏夹 —— 链接 / 图片 / 书单 / 代码片段 / 好物的**两级收藏库**（集合 + 条目）。与 F2（长文）、F3（影视）不重叠。

| 实体 | 关键字段 |
| --- | --- |
| 集合 | `id`、`owner_id`、`name`、`description`、`cover_url`、`visibility`、`sort_order`、`created_at_ms`、`deleted_at_ms` |
| 条目 | `id`、`collection_id`、`type`（url / image / text / file）、`title`、`url`、`thumbnail_url`、`note`、`tags`、`sort_order`、`link_status`（外链类适用）、`created_at_ms`、`deleted_at_ms` |

**功能设计**：集合 CRUD、条目拖拽排序、条目批量移动、标签筛选、**公开只读分享页**（决策 7，走 F8 的分享能力，可选访问口令）、链接有效性检测（低频探测）。

**可见性（决策 2）**：集合默认私有（个人宝库语义）；作者可显式设为公开，公开集合及其条目匿名可读。写操作仅登录作者。

### F5 碎碎念（导航第 5 项）

定位：轻量短动态 / 时间线（类似「说说」），与 F2 的差异是**无标题、无 Markdown、无独立详情页、重发布轻浏览**。

**内容模型（字段清单）**：`id`、`author_id`、`content`（建议上限 500 字）、`images`（URL 数组，最多 9 张）、`visibility`、`pinned`、`created_at_ms`、`deleted_at_ms`。

**功能设计**：主页快捷发布框直达（仅登录态）；时间线用**游标分页**（`before` 游标基于 `created_at_ms + id`），比页码更适合高频插入；按月份归档；置顶与删除；点开为浮层而非独立路由；挂载评论 / 点赞 / 分享（F8）。

**可见性（决策 2）**：默认 `public`，匿名可读时间线；写操作仅登录作者。

### F6 个人资料（下拉第 1 项，决策 6 同批启用）

| 分区 | 内容 |
| --- | --- |
| 展示 | 头像、昵称、手机号**脱敏**、简介、注册时间、内容统计 |
| 编辑 | 昵称（复用现有 1~24 位白名单规则，前后端一致）、简介、头像 |
| 头像方案 | 本地磁盘 `data/uploads/avatar/` + 静态映射；限制类型（jpg / png / webp）与大小（≤ 2 MB）；服务端重采样到 320×320（与现有 `head.png` 规格一致）；重命名存储、禁止目录穿越、禁止脚本执行权限 |
| 库表变更 | `user` 表扩展 `avatar_url`、`bio`、`updated_at_ms` |
| 公开主页 | 决策 2 新增：提供只读公开资料页（头像 / 昵称 / 简介 / 公开内容列表），**不含手机号**，匿名可读 |
| 手机号变更 | 手机号是登录凭证，变更需二次验证，首版只读脱敏展示，不开放修改 |

### F7 账号设置（下拉第 2 项，决策 6 同批启用）

按三个分区组织，直接对应 F0 补强项：

1. **安全**：修改密码（F0-3）、活跃会话列表与踢下线（F0-2）、登录记录（F0-5）。
2. **偏好**：站点显示名、新内容默认可见性（决策 2 后默认 public）、列表每页条数、动态背景模式（复用 `config.js` 的 6 种背景，改为用户级偏好存库）、评论审核开关。
3. **危险操作**：注销账号 —— 采用软删除 + 数据导出，**不做物理删除**；导出内容包含文章、条目、动态、评论与上传文件清单。

### F8 互动（决策 7 新增，横切模块，不新增导航项）

定位：为 F2 / F3 / F4 / F5 提供统一的评论、点赞、分享能力，采用「目标类型 + 目标 ID」多态关联（P10）。

**内容模型（字段清单）**

| 实体 | 关键字段 |
| --- | --- |
| 评论 | `id`、`target_type`（article / media / collection / moment）、`target_id`、`author_id`、`content`、`status`（pending / approved / rejected）、`parent_id`（回复，可选）、`created_at_ms`、`deleted_at_ms` |
| 点赞 | `id`、`target_type`、`target_id`、`user_id`、`type`（like / favorite）、`created_at_ms`；`target_type + target_id + user_id + type` 联合唯一 |
| 分享 | `id`、`target_type`、`target_id`、`token`、`created_by`、`expires_at_ms`、`view_count`、`created_at_ms`、`revoked_at_ms` |

**功能设计**

1. **评论**：仅登录用户可发表（P9），匿名只读；支持一层回复；作者可删除自己内容下的评论；站点级审核开关（默认先审后发，避免开放注册后的灌水）；敏感词过滤；同一用户最小发表间隔 + Redis 令牌桶限流。
2. **点赞**：仅登录用户，一人一次、可取消；计数用 Redis 累加并定期落库，避免高频 `UPDATE`；展示已赞状态需登录态。
3. **分享**：登录用户为任一公开内容生成只读链接（带随机 token、可设过期、可撤销）；**匿名持链接可读**，无需登录；分享页不暴露作者手机号等私有字段；不索引到搜索引擎（页面加 `noindex`）。
4. **多态约束**：无数据库外键，由应用层在创建时校验目标存在、未删除、且当前可见性允许互动；目标被删除时互动数据一并软删除或隐藏。
5. **反灌水（开放注册的必要配套）**：注册限流（F0-7）+ 评论限流 + 审核队列 + 同一内容去重 + 可疑账号人工禁用，四层叠加。

## 5. 鉴权与权限设计

1. **链路复用**：`Authorization: Bearer <token>` → 统一拦截器查询 Redis `blog:session:<token>` → 得到 `userId` → 注入请求上下文。不新增第二套令牌体系。
2. **统一拦截层**：当前 `AuthController` 每个方法手工解析 Bearer。新增模块前应抽出单一解析组件（拦截器或过滤器），否则 30+ 接口会重复该逻辑，且容易出现漏校验。
3. **访客态处理（决策 2 关键改动）**：公开读接口在**无令牌或令牌无效时按访客处理**，返回公开数据，**不返回 401**。现有 `web/js/auth-guard.js` 的强制登录策略须拆分：
   - `optionalLogin()`：有令牌则校验并注入用户信息，无令牌按访客渲染，用于主页 / 列表 / 详情 / 时间线 / 分享页。
   - `requireLogin()`：保持现有行为，用于资料编辑 / 设置 / 编辑器 / 发布页。
   - 顶栏同步新增**访客态**（显示「登录 / 注册」入口）与**登录态**（头像下拉）两套渲染。
4. **三级权限落地**：
   - 公开读：查询条件固定附加 `status = published`、`visibility = public`、`deleted_at_ms IS NULL`。
   - 登录读：私有内容必须校验 `owner_id == userId`。
   - 作者写：更新 / 删除条件同时带 `id` 与 `owner_id`；不匹配统一返回 404（避免资源存在性泄露）。
5. **写操作门槛（P9）**：发布、编辑、删除、评论、点赞、分享生成、上传、资料与设置 —— 一律要求登录。站点开放不等于开放匿名写。
6. **限流**：登录沿用现有失败锁定（5 次 / 60 秒）；注册、评论、点赞、分享、上传用 Redis 令牌桶按用户 + IP 双重限流。
7. **内容审核**：开放注册后必须补评论审核队列（默认先审后发）、敏感词过滤、可疑账号禁用；F7 提供审核开关。
8. **XSS 防护**：Markdown 渲染后做 HTML 白名单净化；前端所有用户文本一律 `textContent` 输出（现有 `home.js` 已如此，必须保持），禁止用 `innerHTML` 拼接用户内容；第三方编辑器自带的预览渲染也必须走同一净化规则。
9. **上传防护**：MIME 与扩展名双重白名单、大小上限、服务端重命名、存储目录不可执行、图片二次编码或重采样。
10. **CSRF**：当前 Bearer 头 + `credentials: 'omit'` 基本不受 CSRF 影响；P4 改 Cookie 会话时必须同步补 CSRF Token 与 `SameSite` 策略。
11. **CORS**：开发保持可配置，生产收窄到具体前端域名（README 已列此为已知限制）。

## 6. 文件与存储方案

| 阶段 | 方案 | 说明 |
| --- | --- | --- |
| 首版 | 本地磁盘 `data/uploads/` + Spring Boot 静态资源映射 | 零新增依赖，符合当前离线 / 单机约束；MySQL 只存相对 URL |
| 演进 | S3 兼容对象存储 + CDN | 需要密钥管理与签名 URL，单独立项 |

**URL 归属决策（必须二选一）**：静态前端在 3000、API 在 8081。上传后的图片 URL 若由 8081 提供，需配置 3000 来源可读取（图片标签不受 CORS 限制，但 Canvas 操作会受）；若落到 `web/assets/user/` 由 3000 提供，则上传写入路径跨服务，需共享目录。建议由 **8081 统一提供**，路径形如 `/uploads/...`，前端拼接 `API_BASE` 使用。

**第三方库资源（决策 4 新增）**：Markdown 编辑器的 JS / CSS / 字体 / 图标 / 高亮主题必须全部落 `web/vendor/` 本地目录，不得引用任何 CDN、远程字体或在线主题；构建后的资源同样纳入 `selfcheck.js` 的零外链扫描范围。

**备份**：MySQL 定期导出 + `uploads` 目录增量备份；Redis 会话为可丢数据（重建即重新登录），不纳入备份。现有 `db/init.sql` 仅建库与 `user` 表，新增表应追加独立迁移脚本，避免改动首次初始化逻辑导致已有数据风险。

## 9. 实施路线（按决策重排）

> 决策 6「一次全开」改变了路线结构：**入口一次性全开，功能按批次填充**。因此 P1 必须先交付全部页面壳，之后才按批次填功能，避免导航指向空白页。

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| **P0 地基** | 统一鉴权拦截器（含访客态处理）、统一响应 / 异常与错误码、分页与游标约定、`user` 表扩展与迁移脚本、上传端点、站点配置项 | 现有 5 个 API 全部回归通过；`verify-stack.js` 36 项通过；匿名读公开接口返回 200 而非 401；越权用例返回 404 |
| **P1 全量入口与页面壳** | 决策 6 + 8：5 项导航 + 2 个下拉项全部启用；6 个业务页 + 分享页同批交付；访客态 / 登录态顶栏；`auth-guard.js` 拆分；品牌统一；**`ui-probe.js` 断言一次性重构 + 反向注入** | 所有导航目标可访问且无白屏；空态 / 加载态 / 错误态齐备；`selfcheck` / `render-probe` / `ui-probe` 全通过；导航文案逐字比对通过 |
| **P2 主干功能 + 互动** | F1 主页聚合、F2 文章（含第三方编辑器本地化）、F6 个人资料、**F8 互动（评论 / 点赞 / 分享）**、F0-7 注册风控 | 文章 CRUD 端到端；Markdown XSS 净化生效；匿名可读、写操作 401；评论审核与限流生效；分享链接匿名可读；头像上传限制生效 |
| **P3 特色与账号** | F3 影视资源（含外链索引与失效检测）、F4 宝库、F5 碎碎念、F0 补强（remember / 会话管理 / 改密 / 审计）、F7 账号设置 | 筛选 / 搜索 / 游标分页 / 可见性正确；影视条目无任何托管文件；改密后其他会话失效；`remember` 长短期 TTL 与「有效期至」一致 |
| **P4 独立硬化（决策 5）** | HttpOnly Secure Cookie 会话改造 + CSRF、限流强化、缓存、备份与恢复演练、生产 CORS、公开内容审核策略复核 | 安全用例通过；性能压测达标；备份可恢复；Cookie 改造后全部验收脚本重新通过 |

每个阶段完成后固定重跑五套验收：`selfcheck.js`、`render-probe.js`、`ui-probe.js`、`apitest.js`、`verify-stack.js`。**P0 是其余阶段的前置依赖**（拦截器与响应约定一旦后改，30+ 接口都要返工）；**P1 是 P2 / P3 的前置依赖**（一次全开要求页面壳先行）。

## 10. 风险与约束

| 风险 / 约束 | 影响 | 缓解措施 |
| --- | --- | --- |
| **一次全开 + 验收脚本断言冲突（最高）** | `ui-probe.js` 40 项断言同时失效；`auth-guard.js` 强制登录与匿名读冲突 | P1 一次性重构断言并保留反向注入；先改断言与守卫，再启用导航；页面壳同批交付 |
| **站点开放 + 开放注册带来的灌水** | 垃圾账号、垃圾评论、垃圾内容 | F0-7 注册限流 + F8 四层反灌水 + 审核队列 + 可疑账号禁用；写操作一律登录（P9） |
| **第三方编辑器与离线自包含冲突** | 引 CDN 即违反 `selfcheck.js`；库内部动态加载远程字体 / 主题同样违规 | 完整本地化到 `web/vendor/`；扫描库内所有资源引用；纳入 `selfcheck.js` 检查范围；选型时验证无运行时远程请求 |
| **影视外链 / 网盘索引合规（决策 3 放宽）** | 若演变为分发入口，存在法律风险 | 只登记纯文本索引 + 来源标注 + 免责说明；不托管文件本体、不提供播放源、不做自动解析跳转；低频失效探测 |
| **多态互动无外键** | 目标删除后残留评论 / 点赞 / 分享 | 应用层校验目标存在与可见性；目标软删除时同步隐藏互动数据；分享 token 可撤销 |
| Web Storage 令牌存在 XSS 风险 | 生产环境账号泄露 | **P4 独立阶段**改 HttpOnly Secure Cookie，同时补 CSRF；本轮不动 |
| Docker Hub 不可达 | 无法拉取新中间件镜像 | 不引入 ES / MinIO / 消息队列等需拉镜像的组件；复用现有 MySQL + Redis |
| 后端无 JPA / MyBatis，手写 JDBC 模板代码量大 | 30+ 接口开发效率与一致性 | 保持现有 `JdbcTemplate` 风格并抽出公共 CRUD 基类；若引入 MyBatis 需先确认依赖可离线获取 |
| 3000 / 8081 双端口 | 上线需统一域名 | 由 Nginx 反代统一入口 |
| 当前 `data/` 下有 JSON 仓储文件（阶段一遗留） | 与 MySQL 双写易混淆 | 明确阶段二为唯一数据源；阶段一只作回退验证，不并行写入 |
| Spring Boot 无单元测试 | 新增模块回归风险 | P0 起补 `spring-boot-starter-test` 用例（依赖已在 `pom.xml`），不以端到端脚本替代全部单测 |

## 11. 决策状态与实施细节

**§0.5 的 8 项决策已全部确认，无阻塞项。** 以下为实施层面的技术选型细节，不阻塞开工，可在对应阶段内确定：

1. 第三方 Markdown 编辑器的具体库与版本（P2 选型，须先通过零外链验证）。
2. 评论审核默认策略（建议先审后发）与敏感词表维护方式。
3. 分享链接默认有效期与是否允许匿名生成（建议仅登录用户可生成、匿名可读）。
4. 站点配置项落在数据库表还是静态配置（建议数据库表，便于 F7 在线修改）。
5. 网盘索引的字段粒度（是否记录提取码、是否做脱敏展示）。
6. 公开资料页是否展示内容统计与注册时间。

## 12. 结论

前端骨架已完整摆出：5 项导航 + 2 个下拉项 + 1 个 Hero 区，共 8 个功能位；后端目前只支撑账号闭环（5 个 API + 1 张表 + Redis 会话）。按本轮 8 项决策，方案从「私密、渐进、无互动」调整为**「开放型博客、入口一次全开、互动纳入首版、引入第三方编辑器、Cookie 改造独立」**，模块扩展为 F0–F8 共 9 个。

三项结构性变化需要在动工前认清：

1. **决策 2 的影响最大**：允许匿名读与现有 `auth-guard.js` 强制登录直接冲突，必须拆出访客态，并新增顶栏双态渲染；同时把「公开读接口返回 401」改为「按访客返回 200」。
2. **决策 6 改变了交付节奏**：不设功能开关意味着 P1 必须一次性交付全部页面壳与完整空态，并把 `ui-probe.js` 的 40 项断言一次性重构。这是全案最高风险项。
3. **决策 7 新增横切模块 F8**：评论 / 点赞 / 分享用多态关联挂在四个内容模块上，配合开放注册必须补齐四层反灌水与审核，否则站点开放后内容质量不可控。

落地顺序仍以 **P0 地基 → P1 全量入口 → P2 主干与互动 → P3 特色与账号 → P4 独立硬化** 为准；P0 与 P1 是硬前置。方案本身不含代码，也未改动任何现有文件，可直接作为实施依据。
