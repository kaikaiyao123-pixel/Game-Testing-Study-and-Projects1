# 背包测试 · 游戏场景与 100 条用例逐项验证

> 独立交付包。两份 HTML 均为**单文件、零外部依赖**，可直接双击离线打开；`src/` 为完整构建与验证链，clone 后可独立复现。

## 1. 定位与来源

本模块把 `day01/` 学习包「测试理论与背包样例」中的 100 条用例清单，落实为**可运行的被测系统（SUT）+ 可执行断言 + 逐项验证结果**，而不是文档式用例列表。

- 用例元数据唯一来源：`docs/第一周学习包_测试理论与背包样例.html` 的 `cases100` 表格，由 `src/extract_meta.py` 自动提取，不人工转录。
- 被测对象：统一背包引擎 `src/engine.js`，采用**服务端权威 + 客户端投影**模型（服务端保存数量、金币、流水与状态，客户端只是投影）。
- Node CLI 与浏览器页面**共用同一份** `engine.js` / `cases_meta.js` / `cases_impl.js` / `runner.js`（UMD 风格导出），避免"演示一套、被测另一套"。

## 3. 快速开始

双击打开 `outputs/背包系统_场景与逐项验证.html`（无需服务器、无需联网）：

- **左侧**：200 格背包场景。击杀怪物 → 掉落 → 拾取，支持使用、锁定、丢弃、出售、拆分、整理，以及断网、重连、时间推进。
- **右侧**：100 条用例逐项结果（可按状态/模块筛选）、6 个缺陷注入开关、"运行验证"按钮在浏览器内重跑全量用例、导出结果 JSON。

`outputs/逐项验证报告.html` 为可打印静态报告；`outputs/测试集_100条.csv` 含文档 3.1 定义的**用例八要素**（编号 / 所属模块 / 标题 / 前置条件 / 操作步骤 / 预期结果 / 设计方法 / 优先级），外加验证类型、基准版状态、实际观测值、注入缺陷版状态共 12 列。

## 4. 验证结果

### 4.1 总体

| 指标 | 基准版 | 注入 6 个典型缺陷后 |
|---|---:|---:|
| 用例总数 | 100 | 100 |
| PASS | **98** | 80 |
| FAIL | **0** | 18 |
| MANUAL（需真机） | 2 | 2 |
| 缺失实现 | 0 | 0 |

验收断言全部为真：`metaMatchesDoc`、`noMissingImpl`、`baselineNoFail`、`reverseEffective`、`injectedDetected`。

### 4.2 用例分布

| 分组 | 条数 | 主要设计方法 |
|---|---:|---|
| A 容量与拾取 | 18 | 等价类、边界值（容量 200 / 堆叠 99 / 数量 0 与负数） |
| B 道具操作 | 22 | 边界值、等价类（使用、丢弃、锁定、出售、拆分） |
| C 状态与迁移 | 16 | 状态迁移（六态合法/非法迁移、限时道具过期） |
| D 判定表：整理规则 | 12 | 判定表 R1–R8（有空格 / 有可堆叠 / 有锁定） |
| E 场景法：完整链路 | 16 | 场景法（断网、杀进程重进、多端并发、重复回调、热更新、跨服、回档） |
| F 兼容、性能与界面 | 16 | 专项（布局、角标、特殊字符、对比度、帧率、音效震动） |

- 验证类型：自动断言 `auto` 91 条、代理验证 `proxy` 7 条、人工验证 `manual` 2 条。
- 优先级：P0 38 / P1 37 / P2 22 / P3 3。

### 4.3 缺陷注入反向测试（证明测试集具备真实检错能力）

| 注入缺陷 | 预期被捕获用例 | 实测扩散到的用例 |
|---|---|---|
| `swallowDrop` 拾取后地面不消失 | A04 | A04, A05, E05 |
| `noExpireCheck` 不校验过期 | C08 | C08, C10, C12, C13 |
| `noIdempotency` 去掉幂等保护 | E09 | E09 |
| `sortMovesLocked` 整理移动锁定道具 | D04 | D02, D04, D08, D12, E03 |
| `purchaseLosesItem` 购买丢单 | A07 / E04 | A07, E04 |
| `badLayout` 布局算法错误 | F01 | F01, F03, F15 |

6 项单独注入均被预期用例捕获；同时注入时出现 18 条 FAIL，说明缺陷会沿链路扩散，而非仅命中单点。

### 4.4 端到端渲染验证

真实 Chrome headless DOM 探针实测：背包网格 200 格、结果列表 100 条、反向测试表 6 行数据、**外部脚本 0 个**（离线自包含）、横向溢出 -15px、浏览器内重跑验证 100 条、游戏场景掉落→拾取链路可用。

## 5. 完整复现

环境要求：Node ≥ 18、Python ≥ 3.9（**无第三方依赖**）；`browser_probe.py` 额外需要 Chrome 或 Edge，可用 `CHROME_BIN` 指定路径，未找到时会跳过并明确提示。

在 `背包测试/` 目录下按序执行：

```bash
python src/extract_meta.py     # docs/ → src/cases_meta.js（100 条元数据）
node   src/run_cli.js          # → outputs/verification_results.json
node   src/build.js            # → outputs/背包系统_场景与逐项验证.html
python src/verify_report.py    # → outputs/逐项验证报告.html
python src/export_cases.py     # → outputs/测试集_100条.csv
node   src/smoke_test.js       # 最小 DOM 冒烟测试
python src/browser_probe.py    # 真实浏览器 DOM 探针（可选）
```

`build.js` 与 `verify_report.py` 在写出文件前执行自检（标签配对、离线依赖、占位符残留、内联脚本语法、模块同源、SVG 几何越界、数据一致性），并各自做**自检反向注入测试**；任一不通过则拒绝写出，避免"永远通过"的空自检。

**复现一致性说明**：`verification_results.json` 的 `generatedAt` 为构建时间戳，页面「生成时间」随之变化；性能类用例的 `打开耗时=Nms` 为单次测量值（阈值 `<500ms`，实测 0–1ms）。除这些非确定性运行时字段外，100 条结果、断言观测值、验收结论与所有交付物内容逐字符一致。已在打包时对照原工作区产物验证通过。

## 6. 诚实边界与已知局限

1. **2 条 `manual` 未标记为通过**：F06（帧率）与 F13（音效/震动）必须在真机上人工验证，逻辑层不能替代。
2. **7 条 `proxy` 为代理验证**：布局算法、对象计数、对比度计算等可在逻辑层验证，但不等价于真机 UI 效果。
3. **源文档 6.3 与 6.2 不自洽**：6.3 的自检标准要求"非法路径 ≥30 条、P0 约 20 条"，而 6.2 清单按严格口径（设计方法含"非法/无效/异常"）为 21 条、宽松口径 24 条，P0 实际 38 条。偏差来自源文档清单本身，未篡改源数据，静态报告中已如实说明。
4. **验证范围**：本包验证的是逻辑层规格（幂等、一致性、状态迁移、判定表、场景链路），不等价于真实网游服务器的并发压力、持久化与网络分区测试。

## 7. 设计要点

- **幂等与一致性**：`use()` / `pickup()` 通过 `opId` + `processed` + `_inflight` 防止重复结算；断网重连要求"要么成功且只扣一次，要么失败且完全不扣"。
- **缺陷注入反向测试**：先证明测试集在基准版全绿，再注入文档中的典型缺陷证明其会变红，避免只验证"没有报错"。
- **数据与展示同源**：CSV、静态报告、页面预置结果、JSON 全部来自同一次真实执行，不存在手工抄录数字。
